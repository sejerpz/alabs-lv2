# Euclides (aLabs) — LV2 prototype

A Euclidean MIDI sequencer for the MOD Dwarf: 5 independent patterns (kick, snare, closed hat,
open hat, zap), each with its own steps / pulses / rotation, host- or internal-clocked. Pure
sequencer, no audio: it drives a sound module over MIDI, by default the companion
[BlipMachine](../blipmachine/) synth plugin (same voice names and default note numbers), but any
MIDI-triggered drum module/sampler works.

Built with [DPF](https://github.com/DISTRHO/DPF) instead of raw LV2, unlike the other plugins in
this collection — see [Build](#build) for what that changes.

## Parameters

Global: `Run`, `Clock` (Host / Internal), `BPM` (Internal only), `Resolution` (1/8, 1/16, 1/32),
`Swing` (50–75 %, MPC-style: 75 delays odd steps by half a step), `MIDI Out`, `MIDI Channel`
(default 10), `MIDI Gate` (ms).

Port order: **Global**, then the **Sequencer** block with every voice's `Mute`, `Steps` (1–32),
`Pulses`, `Rotate`, `Note` and `Level` (drives outgoing velocity). The two blocks are also
declared as LV2 port groups (Global, Sequencer).

`Mute` cuts a voice's MIDI output entirely (no note-on, no note-off).

| Voice | Note (GM) |
|-------|-----------|
| Kick  | 36 |
| Snare | 38 |
| CH    | 42 |
| OH    | 46 |
| Zap   | 37 |

Defaults: kick 4/16, snare 2/16 rot 4 (backbeat), CH 8/16, OH 2/16 rot 1, zap 3/13 rot 2
(polyrhythm).

### Clock

- **Host** (default): follows the MOD transport's BPM and play/stop (`time:Position`), realigning
  position every block and on jumps/loops. Silent while the transport is stopped.
- **Internal**: runs on its own BPM while `Run` is on, restarting from step 0.

### MIDI

Note-on at the exact sample on the same frame as the step, velocity from `Level`, note-off after
`MIDI Gate`. On stop (or with `Run` off): pending note-offs and CC123.

## Source layout

```
Makefile                      top-level build (+ make moddwarf, make sequence)
plugins/Euclides/
  DistrhoPluginInfo.h          DPF metadata (URI urn:andrea:euclides, no audio ports)
  Params.hpp                   parameter table (symbols, ranges, defaults)
  Engine.hpp                   clock, Euclidean sequencer, MIDI — independent of DPF
  EuclidesPlugin.cpp           thin DPF wrapper
lv2-ttl/                       pre-generated TTL, used by cross builds
test/sequence.cpp              offline run: prints the MIDI a pattern would send, no host needed
test/lv2host_test.cpp          minimal LV2 host for manual testing
bin/euclides.lv2/              the assembled bundle (generated by make)
```

No modgui yet: the MOD UI shows the generic control panel.

## Build

Euclides is built on [DPF](https://github.com/DISTRHO/DPF) rather than as a standalone LV2
plugin like the rest of this collection, so the build needs the DPF sources and produces its
bundle in `bin/euclides.lv2` (DPF's own convention) instead of `build/euclides.lv2`.

```sh
git clone --recursive https://github.com/DISTRHO/DPF.git dpf
make            # native build, generates the TTL and copies it into lv2-ttl/
make sequence   # offline MIDI-dump tool -> build/sequence
```

### Build for the Dwarf

**Without the MOD toolchain** (recommended for experimenting):

```sh
pip install ziglang
./build-moddwarf.sh          # -> dist/euclides-moddwarf.tar.gz
```

Zig links against glibc 2.17 and statically includes libc++, so the `.so` only depends on the
Dwarf's libc/libm/libpthread/libdl. The `-z nodelete` flag avoids a crash on process exit after
`dlclose` (the bundled libc++'s static destructors).

**With mod-plugin-builder** (`./bootstrap.sh moddwarf`, workdir `~/mod-workdir`):
`make clean && make moddwarf`.

A generic cross-compiler (e.g. Ubuntu 24.04's `aarch64-linux-gnu-g++`) compiles fine but needs
GLIBC 2.38, too recent for the Dwarf.

In a cross build the TTL generator cannot run, so the files committed in `lv2-ttl/` are copied
instead. **If you change the parameters, run a native `make` first** to regenerate them.

### Install / publish

```sh
make install                                      # into ~/.lv2 (native build)
./build-moddwarf.sh && make publish [DWARF=192.168.52.1]   # hot install on the Dwarf
```

`publish` hot-installs the bundle through mod-ui (the plugin must not be in the current
pedalboard); it checks the binary is an aarch64 build before sending it, same as the other
plugins in this collection.

Pedalboards built against the old synthesized-audio Euclides need `Euclides` reconnected to
`BlipMachine` (or another MIDI-triggered drum module) over MIDI instead of audio — the plugin no
longer has audio ports.

## Offline tools (test/)

- `test/sequence.cpp`: runs a pattern against a simulated host transport and prints the MIDI it
  would send, no LV2 host needed.
- `test/lv2host_test.cpp`: a minimal LV2 host (`time:Position` in, MIDI event count/dump out),
  also useful to run the aarch64 build under `qemu-aarch64 -L /usr/aarch64-linux-gnu` on a PC.

```sh
g++ -Idpf/distrho/src/lv2 -Iplugins/Euclides test/lv2host_test.cpp -o build/lv2host -ldl
./build/lv2host bin/euclides.lv2/euclides_dsp.so 750 h kick_mute=1   # h=host clock, x=internal

./build/sequence [bars] [bpm] [symbol=value ...]
./build/sequence 8 124 kick_pulses=5 swing=62
ALLMIDI=1 ./build/sequence 1 120    # print every MIDI event
```
